3. PRODUCTION RPA FLOW vs. REFERENCE PROBABILITIES — CONFLICT FOUND
================================================================================

The production flow template (.maps_flow_template.json) and the
production pipeline (run_one_phone.py) use a DIFFERENT interaction model
than what's documented in the Master Reference and built in run_full_maps_flow.py.

PRODUCTION REALITY:
    Every phone gets: Save + Share (both unconditional, 100%)
    No photos, no reviews, no directions, no call, no website.
    The flow is hardcoded; probabilities are not applied.

REFERENCE / DOCUMENTATION:
    Master Reference shows a rich probabilistic interaction set:
        Scroll 80%, Photos 60%, Reviews 50%, Directions 40%, etc.
    run_full_maps_flow.py builds flows with these probabilities.

VERIFICATION REALITY:
    The post-run evidence collector (maps_evidence.py) is DESIGNED to detect
    Photos, Reviews, Directions, Call, Website — but these interactions
    never actually happen in the production flow.

    What the production flow ACTUALLY produces:
        - interactions_present: ['Save', 'Share'] (or ['Reviews', 'Save', 'Share'])
        - The "Reviews" detection is a FALSE POSITIVE in many cases because
          the business card already shows "Reviews" as a button label,
          and the uiautomator dump captures it before any click happens.

    What the evidence code EXPECTS but never sees:
        - "image result" / "view photo map" (Photos click evidence)
        - "write a review" (Reviews click evidence)
        - "start" + "min"/"km" (Directions click evidence)
        - "share via" (Share sheet evidence — usually missed because Back dismisses it)

4. HOW THE MAPS RPA FLOW SELECTS WHICH BUSINESS TO INTERACT WITH
================================================================================

METHOD A: Production Pipeline (run_one_phone.py + .maps_flow_template.json)
---------------------------------------------------------------------------

Step 1: The resolver picks a search term and GPS coordinates
    - Example: search_term="pub near me", gps_lat=51.5187, gps_lng=-0.0991
    - These are passed to the Maps flow baker.

Step 2: The Maps flow baker bakes a JSON flow with the search term as a LITERAL
    - In .maps_flow_template.json, the search term is a literal string in
      the inputContent step (e.g. "plumber sidcup" in the template,
      replaced at bake time with the resolved search_term).

Step 3: The flow types the search term into Maps search box and presses Enter
    - Step type: inputContent + keyOption("enter")

Step 4: The flow attempts to click the business name
    - First attempt: click("text", profile.business_name) immediately
      (assumes business is at top of results)
    - If not found: scrollPage (up to 15 attempts) then click("text", business_name)
    - The business_name comes from profile.business_name (e.g. "The Dickens Inn")

Step 5: If the business name text is found, the flow clicks it
    - This opens the business knowledge panel / card.

IMPORTANT LIMITATION:
    The flow does NOT verify that the clicked result is actually the correct
    business. It matches by TEXT LABEL only. If another business has a similar
    name, or if the text match fails, the flow may click the wrong result
    or fail to find any result.

    The post-run evidence (maps_evidence.py) checks if the business name
    appears on screen AFTER the flow completes, but this is not a real-time
    gate — it is retrospective.

METHOD B: Desktop Browser Automation (account-warmer/activities/maps.py)
------------------------------------------------------------------------

Step 1: Search for a random category term
    - Picks from search_categories in maps_data.json
    - Example: "pub near me", "coffee shops near me"

Step 2: Collect result elements
    - Waits for div[role="feed"] div.Nv2PK or div[role="feed"] a[href*="maps"]

Step 3: Browse 1-3 listings
    - For each result: clicks it, records name, scrolls listing panel
    - Skips recently visited (self._state["recent_visits"])

Step 4: Detect business type
    - Reads button[jsaction*="category"] or span.DkEaL text
    - Maps to "cafe", "restaurant", "barber", "gym", "pub", or "generic"

Step 5: Probabilistic interactions (desktop only)
    - view_photos_probability: 0.70
    - read_reviews_probability: 0.65
    - save_place_probability: 0.10
    - get_directions_probability: 0.25 (separate, after browse loop)

    These are REAL runtime probabilities using Python random.random().

SUMMARY OF FINDINGS
================================================================================

1. INTERACTION PROBABILITIES EXIST IN THREE PLACES:
   - Desktop browser automation (maps_data.json): real runtime probabilities
   - Flow builder (run_full_maps_flow.py): build-time probabilities
   - Master Reference: documentation only

2. PRODUCTION RPA FLOW IGNORES ALL PROBABILITIES:
   - The actual .maps_flow_template.json has unconditional Save + Share only
   - No Photos, Reviews, Directions, Call, or Website in production
   - The evidence code is prepared for them but never sees them

3. BUSINESS SELECTION IS BY TEXT MATCH:
   - The flow types a search term, then clicks by text=profile.business_name
   - Up to 15 scroll attempts if not found at top
   - No verification that the clicked result is actually the target business

4. GOOGLE ACCOUNT CAN BE VERIFIED AT RUNTIME:
   - dumpsys account | grep "Account {" returns the account email and type
   - Currently unused in production; could be a valuable provisioning gate
