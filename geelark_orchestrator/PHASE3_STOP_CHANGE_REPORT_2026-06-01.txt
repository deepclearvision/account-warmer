CHANGE A — step_click() accepts error_type parameter (lines ~83-98)

    def step_click(selector_type: str, selector: str,
                   search_time_ms: int = 5_000,
                   serial: int = 1,
                   save_result_to: str = "",
                   remark: str = "",
                   error_type: str = None) -> dict:
        """Click an element found by selector.
        error_type: "skip" or "stop" — overrides the flow-level default."""
        cfg = {
            "filters": [{"type": selector_type, "content": selector}],
            "searchTime": search_time_ms,
            "serial": serial, "serialMin": 1, "serialMax": 50,
            "serialType": "fixedValue",
            "variable": save_result_to,
        }
        if error_type is not None:
            cfg["errorType"] = error_type
        return _step("click", remark=remark, **cfg)

    AFTER:

        fb.click("text", "Directions", search_time_ms=8000,
                 remark="Phase3: Directions (primary)", error_type="skip")
        fb.wait(3000, "Wait after Directions click")
        # Call fallback: skip if not found (allows Start verification anyway)
        fb.click("text", "Call", search_time_ms=8000,
                 remark="Phase3: Call (fallback)", error_type="skip")
        fb.wait(3000, "Wait after Call click")
        # Final verification: hard-stop if neither opened a target screen
        fb.wait_for_element("text", "Start",
                            search_time_ms=5000,
                            remark="VERIFY: Directions route screen (Start)",
                            error_type="stop")
        fb.wait(2000, "Wait after Phase3 verification")

    NOTE: Directions and Call clicks use error_type="skip" so the fallback
    chain works. Only the final "Start" verification uses "stop" — this is
    the hard-abort gate. If "Start" is not found, the flow task fails with
    Geelark status 4 (failed), giving a clear abort reason.

SUMMARY
================================================================================

   config. If the element is not found, the Geelark task fails with status=4
   instead of silently skipping.

2. Directions and Call clicks remain error_type="skip" so the fallback
   chain (Directions → Call → Start check) still works.

3. Shell verification (dumpsys activity activities | grep mResumedActivity)
   runs immediately after the flow task completes, before screenshots.
   It checks for Maps Directions/GeoIntent evidence in the foreground
   activity output.

4. The FlowBuilder class and step constructors now support per-step
   error_type, making it possible to set "stop" on critical gates while
   keeping "skip" on optional interactions.
