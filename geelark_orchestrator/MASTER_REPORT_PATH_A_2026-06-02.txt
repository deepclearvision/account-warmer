## 1. Path A Implementation Summary (2026-06-01)

### What Was Built

**Warm-up browse flow (`build_warmup_flow` in `run_full_maps_flow.py`):**
- Pulls search terms from `account-warmer/data/maps_data.json` categories (food_drink, services, retail, leisure)
- Uses `run_plan.rng_seed` for deterministic randomness
- Integrates `BusinessTracker` (state_tracker.py) to avoid repeating search terms within 7-day TTL
- Builds a Geelark flow: open Maps → search → expand results → browse 1-2 listings by coordinate → light interactions (scroll, Photos/Save) → Back
- Uses `error_type="skip"` so missing elements don't abort

**Primary Maps flow (`build_maps_flow` in `run_full_maps_flow.py`):**
- 3-phase interaction model:
  - Phase 1: scroll card + pick 1-2 from [Photos, Reviews]
  - Phase 2: pick exactly 1 from [Save, Share, Website]
  - Phase 3: Directions (primary) or Call (fallback), verified by "Start" element
- Builds 89-step GAL flow with baked literals

**Runner sequencing (`run_one_phone.py`):**
1. Google account verification (`_verify_google_account()`)
2. Proxy rotation + app-path routing gate
3. IP convergence + freshness check
4. UI Clear Storage (pre-run)
5. **Warm-up GPS** — nearby point from profile
6. **Warm-up flow** — browse nearby listings
7. **Primary GPS re-activation** — business coordinate
8. **Primary Maps flow** — full 3-phase interactions
9. Post-run evidence + final verification

## 4. GAL-Only GPS Test — Galaxy S23 Ultra (2026-06-02)

### Changes Applied
- Removed shell fallback entirely from primary GPS verification
- Replaced warm-up GPS shell activation with GAL baker
- Replaced primary re-activation GPS shell activation with GAL baker
- Set `reuse_flow_id=None` for all GPS stages (always bake fresh)

### Test Result: **FAILED**

| Stage | Result |
|---|---|
| Proxy, account, clear storage | ✅ All passed |
| **Primary GPS (GAL baker)** | ❌ Flow completed but dumpsys=`0.000000,0.000000` |
| **Abort reason** | `gps_mismatch: dumpsys=-0.000000,0.000000 resolved=51.5224,-0.1026` |

### Root Cause
The GAL flow **task completes** (status 3) but the **mock location is never actually injected** on Samsung S23. The GAL flow's UI-based sequence (open app → type coords → tap START) is insufficient on these phones. They need additional shell-level provisioning (`appops`, `settings put secure mock_location_app`, `OverlayService`, etc.) that the GAL flow template does not include.

### Comparison with Previous Test
In the previous test on the same phone (with shell fallback present):
- GAL flow completed, dumpsys showed `mock inactive`
- Shell fallback `_activate_gps_android13()` kicked in
- Map-area tap succeeded, mock activated at `51.522401,-0.102600`
- Warm-up flow completed (49s)
- Shell re-activation **failed** (all taps returned `0.000000,0.000000`)
- Run aborted at `primary_gps_reactivation_failed`

This shows the S23 CAN set GPS via shell, but only **once per session**. After `pm clear`, the first shell activation works. The second fails.

## 7. Options & Recommendations

### Immediate Fix: Hybrid Approach (Recommended)
- **Primary GPS:** GAL baker (works on most phones, shell fallback if GAL fails)
- **Warm-up GPS:** GAL baker (fresh flow, different coords, shell fallback if GAL fails)
- **Primary re-activation:** GAL baker (fresh flow, same coords, shell fallback if GAL fails)

This keeps the GAL baker as the primary path for all three stages (as requested) but adds the shell fallback as a safety net only when the GAL flow completes but dumpsys shows no mock. This is what the code had BEFORE the GAL-only change, and it produced 3/5 successes.

### Alternative Options

| # | Approach | Pros | Cons |
|---|---|---|---|
| 1 | **Keep GAL baker + restore shell fallback** | Works on ALL functional phones | Not pure GAL-only |
| 2 | **Add provisioning to GAL template** | True GAL-only on all phones | Complex, fragile, requires template rebuild |
| 3 | **Exclude Samsung + Y-series** | Clean code | Lose ~40% of fleet |
| 4 | **Add pre-flight GPS health check** | Skip broken phones early | Additional 30s overhead per run |

### Fleet Recommendations
1. **Remove Y77 and Y31** from active fleet — confirmed phone-level failures
2. **Keep S23** but accept that GAL-only will fail — needs shell fallback
3. **A51, Neo7, A22 are fully functional** — clear for production
4. **Consider pre-flight GPS health check** — 30-second smoke test before committing to full run
