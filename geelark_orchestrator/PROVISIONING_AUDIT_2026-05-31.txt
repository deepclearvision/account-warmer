5. ENFORCED vs. ASSUMED — EXACT STATE
================================================================================

ENFORCED (hard gates that abort the run):
  [1]  CSV "provisioned" flag is True
  [2]  CSV "maps_verified" flag is True
  [3]  Phone starts successfully (Geelark status=0)
  [4]  Proxy rotation succeeds (StreamVia control endpoint)
  [5]  Chrome app-path IP matches proxy IP (_verify_app_path_proxy)
  [6]  Shell curl IP matches proxy IP (_get_phone_ip)
  [7]  IP is fresh (different from previous run's interaction_ip)
  [8]  GPS Geelark flow completes (task status = 3)
  [9]  dumpsys location shows active mock at correct coordinates
  [10] UI Clear Storage runs (non-fatal if fails)
  [11] Maps flow completes (task status = 3) — post-run classification
  [12] Search submitted (uiautomator evidence) — post-run classification
  [13] Business found on screen — post-run classification
  [14] >=2 interactions fired — success criterion

ASSUMED (never verified in production code):
  [A] Developer Options are enabled
  [B] Fake GPS is set as mock app via Developer Options UI
      NOTE: "settings put secure mock_location_app" is a SHELL BYPASS, not verification.
      The production run does NOT verify this setting exists.
  [C] Google account exists on phone
  [D] Maps is signed into any Google account
  [E] Maps is signed into the CORRECT account
  [F] Play Store / Play Services interstitial is absent
      NOTE: Only checked via the CSV "maps_verified" flag, not at runtime.

6. CRITICAL GAP: CSV-ONLY STATIC FLAGS
================================================================================

"provisioned" and "maps_verified" are STATIC BOOLEAN FIELDS in the CSV file.

They are:
  - Parsed from CSV by data_adapter.py / data_layer.py
  - Enforced at load time by check_phone_fit()
  - Persisted to SQLite by upsert_profile()

They are NOT:
  - Verified at runtime by shell commands
  - Automatically set by any provisioning flow
  - Updated based on actual current phone state

PRACTICAL CONSEQUENCE:
  A phone whose CSV row has provisioned=1,maps_verified=1 will pass check_phone_fit()
  and proceed to the full run, EVEN IF:
    - Developer Options were reset since CSV creation
    - Fake GPS was uninstalled since CSV creation
    - Maps was updated and now shows a Play Store interstitial
    - The Google account was removed from the phone

The flags reflect THE LAST KNOWN STATE AT CSV CREATION TIME, not current phone state.

The only runtime verification that PARTIALLY overlaps with these flags:
  - dumpsys_mock_check() verifies mock is active  (overlaps with "provisioned" intent)
  - Post-run gather_maps_evidence() verifies Maps worked  (overlaps with "maps_verified"
    intent, but only AFTER the run has already executed)
