3. Second deep-link + tap sequence fails because app is in an inconsistent state

### Verdict: Code issue — shell fallback not idempotent

## Recommended Actions

### Immediate: Fix S23-style failures
The `_activate_gps_android13()` shell fallback is NOT idempotent — it works on some phones only once per session. The fix is to use the **GAL flow baker** for ALL GPS activations (warm-up, re-activation), not just the primary.

### Short-term: Y-series fleet exclusion
Remove Y31 and Y77 from the active fleet. Both have confirmed phone-level Fake GPS failures that no amount of code can fix.

### Medium-term: Pre-flight GPS health check
Before committing to a full run, do a 30-second GPS smoke test: set a test coordinate, verify dumpsys, then proceed. This prevents wasting proxy rotations and warm-up flows on phones that cannot mock GPS.
